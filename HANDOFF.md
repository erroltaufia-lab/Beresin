# Beresin — working handoff

Paste this into a new chat to pick the app up. Everything below describes code
that exists and runs.

## What this is

A marketplace for booking verified tradespeople (*tukang*) in Tangerang
Selatan. Rebuilt from scratch on 27 September 2026 after the original source
was confirmed lost. The evidence behind the rebuild is in
`../BERESIN-HANDOFF.md` — read that first if you want to know what is genuine
and what was invented.

## Run it

```bash
cd ~/Downloads/recovered-apps/beresin && npm run dev
```

Opens on **http://localhost:3200**. Port 3000 belongs to speaksmarter, so
Beresin was moved off the original port.

Node lives at `~/.local/node` and is already on PATH.

## Stack

Next.js 16.2.10 App Router, React 19, Tailwind 4, TypeScript. No backend.
Matches the other recovered apps so the tooling is shared.

Type Plus Jakarta Sans, chosen because it was commissioned as Jakarta's city
typeface. Palette is workwear: graphite ink, warm paper, one hi-vis orange
accent (`#e4572e`), a trust green for verification badges. Tokens live in
`app/globals.css`.

`Biaya {service} di Tangerang Selatan 2026: Rp… – Rp… | Beresin`

## Data

- `lib/services.ts` — six services. **`ac`, `ledeng` and `lainnya` carry the
  genuine recovered price bands. Do not change those numbers.** `listrik`,
  `cat` and `kebersihan` were added in the rebuild and their prices are
  estimates.
- `lib/tukang.ts` — six sample tradespeople. All invented.
- `lib/store.ts` — orders and session in localStorage.
- `lib/order-ids.ts` — a fixed pool of 24 order IDs. The first two are the real
  cuids recovered from the original app.

## Two things that look odd on purpose

**The order ID pool.** The original used Prisma, so IDs were generated by the
database. A static export cannot prerender a page for an ID that does not exist
at build time, so orders draw from a fixed pool and every ID gets a prerendered
page. Deep links work with no server. When a real database goes in, delete
`lib/order-ids.ts` and let Prisma generate IDs again.

**"Simulasikan tukang menerima".** A button on a waiting order that assigns a
tradesperson and a quote. It stands in for the tradesperson's side of the app,
which does not exist yet. Remove it the moment there is a real tukang flow.

## The obvious next steps

1. **Put the database back.** Prisma and Postgres. Keep the `Order` type in
   `lib/store.ts` as the schema's starting point, replace the four exported
   functions with server actions, and drop the ID pool.
2. **Build the tradesperson side.** Right now `/cara-kerja` says "untuk Pemilik
   Rumah" and there is nothing behind that implication. Tukang need to see
   incoming jobs, quote them, and mark them done.
3. **Real auth.** WhatsApp OTP is the obvious fit for the market.
4. **More services and real prices.** Survey actual rates in Tangerang Selatan
   and replace the three estimated bands.
5. **Photos on orders.** A picture of the broken thing would cut a lot of
   back-and-forth before a quote.
